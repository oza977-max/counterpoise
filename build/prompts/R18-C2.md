## Chunk Summary

Put the reading on screen. When the person presses Continue after the similar-cases check, the description is read by the model they set up. They see a reading step with a Skip control, then land on the form with pre-filled answers. Each pre-filled answer shows the quote it came from and its own "is this right?" tick. Continue stays shut until every pre-filled answer is ticked or changed. From then on the answers travel as one `answerState` through every later step, and the verdict is built only from confirmed form answers. With no model, or after any failure, the person lands on the empty form with the one honest sentence for that failure.

This chunk makes the present-tense "Your description will be read…" sentence true, which lifts the R18-B merge gate (the branch still merges only after G).

Build checks BC-001…006 apply throughout:
- **BC-005, the one that matters most:** every new sentence gets a false-state test. Examples: "from your description" is absent once the quote has left the text; "confirmed by you" is absent while an answer is unconfirmed; the confirmation line is absent when N = K = 0.
- **The audit-trail guard:** any button that can fire twice (Read again, Skip, Continue) needs a synchronous `useRef` guard where it writes or calls.
- **Reserved words:** no new string contains "approved" or "rejected". All new copy goes in `R18_COPY`.

## TDD Approach (TDD-1)

   2. presses Next, then Continue;
   3. sees the reading step;
   4. lands on the form with Question 5 and Question 11 pre-filled, quotes visible;

   6. ticks both answers, then Continue is enabled;
