## What was built (plain words)
1. When a person confirms a case, the record now says where every answer came from (typed, filled by a model and ticked, changed, or carried from an earlier record). It is written once, on that attempt's `graph_confirmed` (or on `verdict_corrected` for a correction). D1's register lines now show real cases.
2. In the submitter view, the register detail has "Correct this check". It reopens the case on the form with every answer restored. **Owner decision 2026-10-22:** answers a model filled in, or answers carried from an earlier record, come back with their quotes but need the correcting person's own tick again, so a self-asserted or forged record can never make the new record claim ticks the person never made. The same-session "Change an answer" keeps its ticks (TC-R18-GI-10-05). Back is refused; confirming writes a `verdict_corrected` with the new sources.
3. A correction writes the corrected description only when it differs from the one now in force, so putting the first text back is recorded.

## Decisions and deviations
1. **Original graph rebuilt.** The register keeps no graph, but the correction flow needs one to diff against (else it records "no answers changed"). Rebuilt from the restored answers by `plainAnswersToFormValues` + `buildGraphFromForm`, versioned from the verdict. Node ids are new; recorded in §27.10.
2. **Action offered only when the record restores enough** (description not blank, every required question answered). Otherwise absent: the older-case path (E).
3. **Opening replaces an unfinished check in the tab** (same reset as "Start over"). The action's note says so.
4. **`lastRead` seed** `{ fingerprint of the opened description, outcome 'not-read' }`: no model call, and no claim of a read this session.
5. **`answersFromRecord`** lives in `answer-sources.ts` (as the prompt says), not `answers-from-record.ts` (§27.1 and the guide name that file for E's older-case mapping).
6. **Double-press** is stopped by two layers (the `confirmInFlight` ref, and the case lock + `confirmationPrecondition`). The test counts events; removing the ref alone does not fail it, because the lock/precondition still refuses the second.
7. `handleCorrectVerdict`'s record fallback is unreachable through the UI (`lastConfirmed` always carries `answerState` for form cases); covered by the reducer test and the shared helper, not by a screen test.
