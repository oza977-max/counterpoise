## What was built (plain words)
Everything needed to let a model read a description and suggest answers. None of it is on screen yet; R18-C2 connects it.

- **The questions now live in the engine.** Each question has a fixed list of options, the rules for when it shows, and which later answers it clears. The form uses the same rules, so the form and the model cannot disagree about which answers are valid.
- **A checker for the model's answers.** Every answer the model suggests must:
  - be a real option for a question that is actually showing, and
  - come with a short quote copied word for word from the description.

  Anything else is dropped, with a recorded reason. A suggestion never overwrites something the person typed, changed or confirmed. A suggestion the person's own answers rule out (for example a zone their chosen platform doesn't offer) is not written.
- **The call to the model.** It sends to the address from the person's setting only after checking that setting again. It tries the model's two answer modes in order, and waits a fixed maximum time. Every safety flag is set on the request. A failure is sorted into one plain reason; the server's own words and the description never appear in any message or log.
- **One plain sentence per failure.** Each reason has its own sentence, worded for Ollama or for a firm's server.
- **A reading "hook" for the screen.** It runs one reading at a time, with a 30-second limit and a Skip button. It stops if the setting changes or the person leaves, keeps the first stop reason, and ignores late replies.
- **A test harness** that records every way the page could send data out. Its tests prove the description goes only to the configured address.

## Deviations from Spec
1. `mergePrefill(answerState, prefill, catalogue, policy, read)` takes a 5th parameter, `read`, the only way the read record gets in. `clearDependents(..., before?)` takes an optional `before`. Both are now written into §27.6.
2. `isValidMultiSelection` checks structure only. A multi-select conflict keeps the first option. `3aWhich` is "not scored" (the real policy cannot show it).
3. `too-long` (more than 8,000 code points) is decided in `requestPrefill`, before any send.
4. Classifier order is provisional:
   - body words count only for statuses below 500;
   - allowance and plan words count only on 403;
   - 402 → `not-included`; 429 → `allowance-used`;
   - an unmatched 400 → `other` (400 in tool mode stays `unusable`).

   C0 tightens this with captured replies.
5. Format-mode reply parsing tries the span from the first `{` to the last `}` when plain JSON parsing fails. The verifier still checks everything.
6. A `nothing-found` read does not record the answer mode that worked. The cost is one extra full send of the description the next time if the format mode fails again. This is a privacy cost to note, not a bug.
7. The hook settles at once on skip, timeout or setting change. It ignores the late reply rather than waiting for it.
8. §27.5 sentence changes, mirrored in both twins:
   - The cloud place gets its own `model-missing` sentence.
   - The `not-answering` (5xx) sentence says "answered with an error", not "start the app".
9. The Anthropic SDK captures `fetch` at import, so `egress.test.ts` mocks `./client` (NF-3-05 proves the host only). Other SDK-path tests could reach the real network if a real key were ever set in the test environment.
10. `'leave'` maps to `not-read`, which is never shown.
