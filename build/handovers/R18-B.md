## What was built (plain words)
Settings now asks *where* the description-reading model runs — on this computer, on the firm's server, or Ollama's cloud through the Ollama app — and checks the address for that place: a look-alike or credentialed address is refused, a cloud model is only allowed under Ollama's cloud, and that choice needs this computer's address. "Find models" lists what the server reports (only when pressed, never while typing) and the person can always type a name; no model is named or recommended anywhere. Above the Next button the description screen says, in one plain sentence, where the description will go — "never leaves your computer" only for a valid this-computer setting with no stored Anthropic key — plus the unencrypted line for a plain-http firm server, the demonstration notice for any place other than this computer, and the shared-site note on the public github.io demo. A setting that fails the checks says so instead of making any promise. "Clear all data" keeps the model setting, says so (only when one exists), and offers "Forget the model setting". The self-assessment seed no longer reads any setting. Free-text answers are limited to 200 characters (the description is not).

2. `aigate:model-test-results` stored as `{ version: 1, results: [...] }`, newest first, capped at 20 — R18-F appends to this shape.
3. Save button reads "Save the model setting" (plain "Save" collided with an existing test query).
4. `modelSettingState()` added (none / invalid / no-model / valid) so the screens can tell "no model" from "invalid".
5. `updateModelSetting` validates the merged result and returns `{ ok, setting } | { ok: false, reason }`.
6. A migrated URL-only old setting is stored with an empty model and reads "No model is connected." until a model is chosen.
7. Settings previews the sentence for unsaved form values, marked "Not saved yet. Press Save to use this."
8. **Merge-gate note:** the present-tense where-it-goes sentence ("Your description will be read…") is shown although no reading exists until R18-C2. Acceptable only because `round-18` merges after R18-G; the branch must not be merged or previewed publicly before C2.
