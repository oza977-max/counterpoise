## What was built (plain words)

The register's case detail now says where each saved answer came from, and the hand-off file carries and checks the same record.

1. When a case carries `answer_sources`, a block above the verdict shows:
   - one line per distinct read, naming the model and where it ran, in the past tense ("read by alpha:7b by the program at http://localhost:11434 on the computer in use");
   - one honest note under those lines: the model and place are what was set up, and Counterpoise does not check them;
   - the same "N of M answers were filled in by a model and confirmed by you" line as the confirmation step, counted from the rows;
   - per answer: the question, its value in words, and who supplied it (typed by you; filled from the description and confirmed, with the quote and the model that suggested it; changed by you, from what, with the quote; from the earlier record; or "source not recognised");
   - "the quote is no longer in your description" on exactly the answers whose record says so.
2. A case with no `answer_sources` renders exactly as before. The existing RegisterDetail, RegisterView and hand-off tests ran unchanged and pass.
3. The hand-off file validates `answer_sources` with every bound of §27.13, refuses `__proto__`, `constructor` and `prototype` as keys anywhere under it, tolerates the unknown words a newer build may add, and stays at format version 1.
4. A correction's description (`verdict_corrected.description`) is read, and shown under "Description, as corrected".
5. The hand-off screen says plainly what the file is: the export message ends with "This file contains the descriptions and quotes of every case in it." (only after an export), and the screen always says the sources in an imported file are whatever its maker recorded.

## Decisions on tolerated unknowns (recorded in §27.13, md and html)
- **Unknown origin word:** the line reads "source not recognised"; the word is never shown.
- **Unknown place word:** "read by {model} at {host}, a place this version doesn't recognise"; the word is never shown, the host still is.
- **Out-of-range or non-integer `read`:** the row shows without "suggested by {model}". Nothing throws; the read lines come from `reads`.
- Unknown question id or option key: the raw text, no "value in words".
- Origin wording: the model is named after the quote, "(suggested by {model})", so the spec's phrase "filled from your description and confirmed by you" stays intact.

## Deviations from Spec
1. Extra bounds the spec left open: value array ≤ 100 strings, `origin` and `place` ≤ 100 characters, corrected `description` ≤ 1,000,000, nesting ≤ 12. All recorded in §27.13.
2. For `prefilled_changed` the reader uses `changed_from`, falling back to `quotes`. §27.13 lists both fields for that origin without saying which the register reads.
3. A correction without `answer_sources` shows none, even if the first confirmation had them. An older confirmation's rows would describe answers the correction may have changed.
4. The export statement sits in the export success message and the provenance sentence in an always-visible paragraph, not in a separate export "screen"; the app has no such screen.
5. Question labels are the form's full question text (e.g. "What information will it see or use? Tick all that apply."). Option words are full option text. Accurate, but long; a shorter label table is a possible polish.
